# ShadowTrack MVP — фактический результат

**Acceptance: P0_PASS / GLOBAL_ASSOCIATION_PENDING.** Рабочее CPU приложение
запущено через Docker Compose. Импорт, локальный трекинг, полные видео, API,
React и настоящий browser E2E работают. Подтверждённых межкамерных эпизодов — 0;
истинное число сквозных эпизодов и физических людей пока не установлено.

## Реальные входы

Прочитаны `shadowtrack_full.zip` и `shadowtrack.ipynb` из Downloads, оба PDF
дизайнера, AGENTS/README, исходное ТЗ из сохранённого source audit, результаты
Data Audit, Time Alignment и выполненных GPU прогонов. PDF использованы как
визуальные референсы, а не как инструкции для изменения данных.

FULL run `3f764abf202cfb544e6f6a67`, `small_640`, batch 8, Detection schema v2:

- 5 камер, 144 110 обработанных кадров, 1 135 чанков.
- 136 020 raw bbox; accepted 85 445, rejected 26 248, uncertain 24 327.
- 84 904 кадра без raw bbox; их записи сохранены.
- COMPLETE, export inventory, SHA256, model lock, frame order и все raw PTS
  проверены существующим импортёром. Исходные MKV и detection records неизменны.
- Повторного YOLO, обучения, ручной разметки личностей и облачной загрузки не было.

Новый локальный replay: `supervision.ByteTrack==0.25.1`, activation 0.30,
lost buffer 45, matching 0.80, minimum consecutive frames 3. Он занял около
45 секунд CPU и дал **503 локальных фрагмента / 81 357 наблюдений**. Это не
503 человека. Rejected кандидаты не создают треки; source indices, PTS и
timestamp boundaries сохранены. Пороги и replay manifest записаны отдельно.

## Эпизоды и правило 1–2 минут

Принят таймаут **120 секунд** отсутствия. Короткий буфер ByteTrack и завершение
эпизода — разные понятия. `active/lost/terminated` и причина завершения хранятся
отдельно; после истёкшего таймаута старый episode ID не восстанавливается.

В локальном домене доступны 503 эпизода фрагментов: 366 terminated, 128 lost,
9 active на конце доступного сегмента. Это конечные состояния архивного анализа,
не текущая живая занятость офиса. На границе временного сегмента неизвестное
продолжение не превращается в доказанное отсутствие.

Завершить глобальный эпизод по отсутствию во всех ракурсах можно только при
поддержанном покрытии всех пяти камер. Глобальная временная привязка сейчас
PARTIAL; это ограничение не скрывается локальными состояниями.
Граница 60/90/120 секунд, непродолжение завершённого эпизода и неизвестное
покрытие отдельно проверены unit tests.

## Настоящий Re-ID и предел глобальной части

Использован pretrained **OSNet x0.25 / MSMT17 combineall** из репозитория автора
`kaiyangzhou/osnet`, MIT. Архитектура взята из фиксированного Git commit и
проверена SHA256; веса 9 336 983 bytes, SHA256
`cf55163d78fc44c62c82f85ab62d39f10438679b5abe8c698ae08cfa84aa6e18`.
Classifier обучающих личностей не используется; все параметры feature encoder
загружены из проверенных весов. Случайных embeddings нет.

CPU реально обработал **1 523 исходных кропа** и сформировал 512-dimensional
L2-normalized признаки для **390 локальных треков**, по 3–4 независимых кадра.
Чистое вычисление encoder заняло около **10.34 s**; сюда не включены подготовка
кропов, установка PyTorch и дисковый экспорт. Проверены исходный run, camera,
frame index, raw PTS, bbox, hashes, нормализация и согласованность нескольких
наблюдений. Для остальных коротких/неподходящих фрагментов признаки не выдуманы.

208 кандидатов остались UNRESOLVED:

- 208 не имеют полного подтверждённого временного интервала.
- 189 имеют конкурирующие похожие наблюдения.
- 107 дополнительно не проходят порог внешнего сходства.

Причины могут пересекаться. Поддержка времени камер 1↔3 ограничена примерно
0.195–3.530 s общей условной координаты; остальные камеры не откалиброваны.
Similarity не заменяет время или identity evidence. Ни один удобный offset
не назначен для получения красивого global ID. Полноценная межкамерная часть
остаётся **PARTIAL/PENDING**, а не объявляется решённой по похожей одежде.

Реализованы multi-crop embeddings, cosine scores, конкурентные кандидаты,
временные ограничения, качественная смежность плана и конфликты одновременных
наблюдений. Причины, confidence и источники сохраняются. После ручной временной
калибровки ассоциации инвалидируются и пересчитываются явно. Исходный Time
Alignment Engine и его JSON/NPZ не изменяются.

Опциональный `notebooks/kaggle_reid.ipynb` импортирует тот же encoder, работает
с распакованными приватными папками и экспортирует NPZ + manifest без изображений.
В текущем результате GPU для Re-ID не потребовался.

## Видео и интерфейс

Созданы 5 полных browser H.264 MP4 и **15 полных аннотированных MP4 сегментов** —
по три timestamp segment на камеру. Суммарное покрытие аннотированных файлов:
**144 110 / 144 110 кадров**, без дублей и пропусков. Они не склеиваются через
недоказанные разрывы. Рендер 960×720, CPU, два worker: около **1 701.69 s**.

Исходные bbox, стабильные цвета, локальные ID, confidence, camera, raw PTS и
короткие trails берутся из сохранённых записей. MP4 labels используют исходный
номер ByteTrack в пределах камеры/сегмента; UI даёт удобный alias Cn-Txxx.
Полный исходный namespace сохраняется в machine records и Track Detail API.
Неподтверждённые global ID не рисуются.

Для камеры 4 HEVC преобразован в H.264 с **encoder time base 1/1 000 000**;
квантование к номинальному 1/20 не используется. Для всех browser и annotated
MP4 проверены codec, число packet/frame samples и соответствие каждого PTS
сохранённому аудиту/sidecar. Итоговая ошибка PTS в проверке — 0–1 μs.
Повторный полный probe исходных MKV не запускался.

Созданы три настоящих highlight-клипа: проход камеры 1, двери камеры 3, коридор
камеры 4. Они получены из готовых аннотированных видео, без инференса.
Их таймкоды относятся к разным локальным шкалам и не выданы за общее событие.

React + TypeScript/Vite/Tailwind, Lucide, TanStack Query, Router. Повторены
основная структура, чёрно-белая палитра, лаймовый акцент, hero, карточки, CTA,
план и панель камер из desktop/mobile PDF. Assets извлечены из предоставленного
дизайна. Дополнительные рабочие экраны продолжают ту же систему.

Действительно работают: переключение камер по карте, пять плееров в сетке,
Play/Pause/seek, 0.5×–4×, Detection/Local/Global modes, выбор bbox, история,
поиск/фильтры треков, события, аналитика, калибровка и скачивание результатов.
Общий пульт по умолчанию использует относительные шкалы источников. Поддержанный
global mode явно отключает камеры без временной привязки. План показывает точки
выбора камер, а не выдуманные координаты людей.

Покадровые данные остаются основой: `/api/exports/tracks.json` потоково отдаёт
все кадры, включая пустые; JSONL.GZ доступны отдельно на каждую камеру. CSV —
сводка. Весь массив кадров не загружается в браузер одним API-запросом.

## Backend, хранение и Compose

FastAPI, Pydantic input validation, health, structured HTTP logging, CORS,
bounded overlays и indexed SQLite WAL. Миграция `schema_version=1` находится
в `mvp/db.py`; база около 55 MB, практична для одного CPU ноутбука.
PostgreSQL для этого MVP не обязателен. Видео отдаются через HTTP Range
(проверены 206/416) и nginx proxy, без полной загрузки в память.

Образы действительно собраны, Compose запущен; backend healthy. Оба сервиса
привязаны только к localhost. В backend контейнере **torch не установлен**,
GPU для веб-приложения не нужен. Исходники/configs подключены read-only,
данные/результаты находятся в volumes, а не внутри образов. Подготовка CV
выполняется отдельной командой, не на каждом запуске сайта.

Уже открывается http://localhost:3000; Swagger http://localhost:8000/docs.
Повторный запуск готовых образов: `docker compose up -d`. Первая/новая сборка:
`docker compose up --build -d` (скачивание зависимостей зависит от сети).

## Ограничения при защите

Нет ground-truth identity labels, поэтому не заявлены IDF1, число физических
людей или измеренная точность межкамерной ассоциации. ByteTrack может дробить
ID после перекрытия/разрыва; дальние фигуры, ТВ и похожая одежда остаются рисками.
120-second timeout — правило эпизода, не доказательство ухода из всех ракурсов
при неизвестном временном покрытии. Для полноценных global episodes нужны новые
проверенные временные события/калибровка и разрешение конкурирующих ассоциаций.
