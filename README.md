# ShadowTrack

**Пять камер → детекции людей → локальные треки → общие трек-эпизоды → веб-интерфейс.**

CPU-приложение для хакатона NTechLab: Python/FastAPI, React/TypeScript и Docker
Compose. Тяжёлые детекции YOLO уже получены в Kaggle; при обычном запуске и
пересчёте связей GPU не нужен.

> **Для запуска нужен код + отдельный приватный комплект данных.**
> В Git/source ZIP нет исходных MKV, подготовленной базы и браузерных MP4.
> Чистый clone без этих файлов не запустит готовое демо.

## Быстрый запуск готового демо

Нужны Docker с Compose и Python 3.11+ для проверки/распаковки комплекта.
Node.js, локальные torch/YOLO и модельные веса для этого сценария не нужны.
Команды выполняются **из корня проекта**, где лежит `docker-compose.yml`.

1. Получите актуальный код — полную рабочую копию либо свежий source ZIP.
2. Отдельно получите `shadowtrack_demo_data.zip` от владельца данных.
3. Восстановите папки и проверьте комплект:

```powershell
python scripts/handoff.py restore --source "C:/PRIVATE/shadowtrack_demo_data.zip"
python scripts/handoff.py check
```

4. Запустите приложение:

```powershell
docker compose up --build -d
docker compose ps
```

Открыть **http://localhost:3000**. API: http://localhost:8000/docs.
Проверка готовности: http://localhost:8000/api/health — `READY`, пять камер.
Первый build скачивает программные зависимости; видео никуда не загружаются.

Если данные уже лежат на своих местах, достаточно `check` и `docker compose up`.
Запуск контейнеров использует сохранённый snapshot и не повторяет CV pipeline.

## Что должно лежать рядом с кодом

```text
ShadowTrack/
├── docker-compose.yml
├── src/  frontend/  configs/  docs/
├── data/
│   ├── raw/camera_new_1.mkv ... camera_new_5.mkv
│   └── metadata/office_camera.png
└── artifacts/
    ├── sync/time_alignment.json + пять *_frame_times.npz
    └── mvp/
        ├── server/snapshot.json + snapshot.sqlite3
        ├── media/          # MP4 и sidecars из подготовленного комплекта
        └── local_tracks/   # manifest.json + пять *_tracks.jsonl.gz
```

Распаковывать нужно **в этот корень**, а не во вложенную папку `repo/data-pack/`.
`handoff.py restore` восстанавливает пути сам, проверяет SHA256 и не заменяет
существующий файл, если его содержимое отличается.

Минимальный комплект текущего демо: **79 файлов, 1 345 352 709 байт** до ZIP.
Он включает закрытый snapshot, исходные видео, все индексированные MP4,
машинные треки и временные привязки. Признаки внешности уже находятся в SQLite.

Владельцу подготовленных данных:

```powershell
python scripts/handoff.py manifest
python scripts/handoff.py pack --output "artifacts/handoff/shadowtrack_demo_data.zip"
```

Первая команда создаёт список путей/SHA256 в `artifacts/handoff/demo_manifest.json`.
Вторая по явному запросу создаёт **приватный** архив данных и `.sha256`.
Передавать его нужно отдельно от source ZIP. Для восстановления детекций/признаков
с нуля нужны дополнительные входы — [точный список](docs/MVP_SETUP.md#данные-для-воспроизведения-обработки).

## Как пользоваться

- **Монитор → Карта:** выбрать камеру на плане.
- **Люди:** увидеть приблизительные точки глобальных ID и выбрать трек.
- **Камеры:** несколько реальных ракурсов под общим play/pause/seek.
- **Треки:** одна карточка на глобальный эпизод; внутри камеры и интервалы.
- **Gantt:** история наблюдений и переход к нужному фрагменту видео.
- **Связи:** причины автоматического сопоставления и явный CPU-пересчёт с прогрессом.
- **Аналитика / Экспорт:** счётчик и машинные данные.

[CSV эпизодов](http://localhost:3000/api/exports/episodes.csv) ·
[JSON эпизодов](http://localhost:3000/api/exports/episodes.json) ·
[Все кадры с треками](http://localhost:3000/api/exports/tracks.json)

Скачанные MP4 с **локальными** ID — исторический производный результат.
Текущие глобальные ID рисуются в браузере из актуальной базы.

## Текущий результат и границы готовности

- Обработаны пять MKV: **144 110 кадров**, включая пустые; **136 020 raw bbox**.
- ByteTrack: **503** исходных фрагмента; после временного разделения — **524**.
- Получено **281 автоматический трек-эпизод**, из них **30** наблюдаются на нескольких камерах.
- В replay-ведомости: 149 завершены; у 132 окончание не подтверждено из-за
  конца записи/пробелов покрытия. Таймаут — 120 секунд.
- Последняя проверка CV/MVP: **189 CPU tests + 20 Chrome E2E**. Для утилиты
  передачи дополнительно проверены восстановление, SHA256 и защита исходных файлов.

Это число **эпизодов алгоритма**, не число физических людей и не ground truth.
Сохранение ID на всей записи подтверждено частично: контроль 13 положительных
и 4 отрицательных случаев проходит, полной независимой оценки IDF1/HOTA нет.
Положение на карте приблизительное. Плееры используют исходную шкалу записей
организаторов; доказанная временная калибровка всех пяти камер не заявляется.

По ТЗ есть интерфейс, детектор, локальный и собственный межкамерный алгоритм,
таймаут, счётчик и перечень эпизодов. **Полное качество ID остаётся открытым**;
выдавать решение за безошибочное выполнение ТЗ нельзя.
Подробности и неоднозначные формулировки — [проверка ТЗ](docs/MVP_REPORT.md).

Документы исходного аудита описывают состояние своего этапа и не заменяют
актуальную инструкцию запуска.

**Передача через Git:** в текущей рабочей копии есть незакоммиченные и новые
файлы, включая MTMC и документацию. Перед clone коллегами нужно включить их
в коммит и передать этот коммит. Для передачи текущего состояния доступен
source ZIP, создаваемый `python scripts/build_mvp_bundle.py`; его состав
фиксируется manifest/SHA256. `.venv`, `.tools`, `node_modules`, Docker volume
и приватные результаты не являются переносимым репозиторием.
