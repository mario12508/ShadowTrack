# ShadowTrack — автоматические Global Episodes

Обновление 8 ноября 2026. **Acceptance: IMPLEMENTED_ESTIMATED_MVP_WITH_PARTIAL_IDENTITY_VALIDATION.**
Пять камер воспроизводятся при любых статусах синхронизации. Основной ID вычисляется
автоматически; ручное подтверждение не требуется. Это оценочное межкамерное
отслеживание, не доказанная идентичность всех людей за всю запись.

## Проверка требований и полировка интерфейса — текущая ревизия

Статус видео «есть регрессия» пользователь уточнил как относящийся к предыдущей
проверке. Подтверждённый текущий дефект: вкладки «Карта» и «Люди» показывали один
компонент с одинаковыми параметрами. Теперь «Карта» выбирает камеру на плане,
«Люди» показывает точки треков и список наблюдений. Вкладки используют разные
состояния, при переключении между ними текущий video element сохраняется.

Дополнительно исправлены сброс global selection, неправильный global ID в ссылке
на вторую сторону кандидата, обработка ошибки пересчёта и загрузки видео,
неправильное объяснение завершённого эпизода. Миниатюры камер больше не запускают
новое декодирование каждые пять секунд. Из сетки видео убраны sync badges;
показывается фактический FPS. Оба HTTP маршрута пересчёта используют одну блокировку,
повторный одновременный запрос получает 409. Этапы и heartbeat доступны через
`/api/mtmc/progress`, а на странице «Связи» видны стадия и прошедшее время.

Проверка всех девяти требований:

1. **Пять записей — проверено:** 144 110 кадров, все камеры 1–5; камера 4 — 20 FPS,
   остальные около 25 FPS. Исходные MKV сохранены.
2. **Детекция людей — реализована:** FULL содержит 136 020 raw bbox и отметки пустых
   кадров. Это факт обработки, не измеренная полнота/точность детектора.
3. **Рамки — проверено:** browser overlay рисует bbox и ID из сохранённых данных;
   исходные аннотированные local-ID MP4 также доступны.
4. **Локальный трекинг — реализован:** 503 ByteTrack-фрагмента, 81 357 observations.
   Локальные ID и исходные observations не переписаны.
5. **Веб-видео — проверено текущим браузерным прогоном:** переключение ракурсов,
   play/pause/seek, отдельные режимы карты/людей и восстановление после ошибки media.
6. **Одинаковый ID между камерами — частично подтверждено:** 30 межкамерных эпизодов;
   известные пользовательские случаи и контроль 13/13 positive, 4/4 negative проходят.
   Полная точность ID на всех кадрах неизвестна.
7. **Отсутствие 1–2 минуты — реализовано условно:** выбран timeout 120 s. Ведомость
   использует фактические наблюдения в шкале воспроизведения исходных записей.
   149 эпизодов завершены, для 132 завершение не подтверждено: конец записи либо
   пробел покрытия. Из последних 132 один виден в последнем кадре, 131 потерян.
   Окончание файла не выдаётся за доказанный выход человека.
8. **Подсчёт сквозных эпизодов — реализован как результат алгоритма:** **281** ID,
   включая **30** эпизодов с несколькими камерами и **251** с одной камерой.
   По ТЗ эпизод, прошедший несколько камер, учитывается один раз. Однокамерные
   эпизоды также входят в общее число. Это не ground truth и не число людей.
9. **Корректность ID на реальных данных — частично:** есть малая повторно
   использованная контрольная выборка, нет полной независимой разметки/IDF1/HOTA.
   Поэтому итоговая acceptance не означает 100% точности MTMC.

Состояния счётчика зависят от текущего playhead: будущие эпизоды ещё не «начались»;
между реальными observations показывается lost. Ведомость хранит исходные интервалы,
максимальный пропуск наблюдений, камеры, fragment IDs и окончание по таймауту.
Её clock=`source_recordings`; canonical aligned timestamps хранятся отдельно.
Общая измеренная временная калибровка пяти камер не заявляется.

Новые API/экспорты: `/api/episode-counts?time=SECONDS`,
`/api/exports/episodes.json`, `/api/exports/episodes.csv` — одна запись на эпизод.
Архив, детали и счётчик используют одинаковый replay lifecycle. Исторические
Time Alignment и raw PTS неизменны. Обычный пересчёт не запускает inference.

Из 195 не связанных source fragments: 68 короче 1 s, 82 длиной 1–5 s, 45 длиной
не менее 5 s. В первую очередь полезно исследовать 45 длинных фрагментов;
короткие закрытые фигуры нельзя автоматически считать ни шумом, ни доказанным ID.

Проверки и точные статусы девяти требований:
`artifacts/mvp/mtmc/acceptance_progress.json`. Ведомость:
`artifacts/mvp/mtmc/episode_accounting.json`, числа: `episode_counts.json`.

Первый холодный браузерный прогон дал 15/20: проверки готовности media/track
имели короткий лимит 5 s, один legacy playback сценарий проверял скрытые плееры.
Теперь ожидание начальной готовности — до 20 s, а пятикамерные playback сценарии
проверяют все пять действительно видимых видео. Проверки движения времени,
отсутствия seek/backwards и dropped frames не ослаблены. Повторный прогон —
20/20. Первый результат сохранён в `playwright-initial-polish-run.json`.
При загрузке трека больше не показывается технический hash как локальный ID;
видео показывает загрузку кадра и позволяет повторить запрос после media error.

Внутренняя проверка всей текущей группировки: конфликтов одновременных разных
треков одной камеры не найдено; 34 перекрывающиеся пары имеют геометрическую
поддержку nested boxes. Максимальный общий пропуск наблюдений — 116.582 s;
эпизодов с внутренним пропуском ≥120 s нет. Это self-consistency, не ground truth.

## Что реализовать за следующий час

- **0–10 min:** ранжировать 45 длинных несвязанных фрагментов по причине отказа,
  качеству crops, соседним portal transitions и конкурирующим кандидатам.
- **10–30 min:** улучшить продолжения у дверей и восстановление после окклюзии
  из существующего кеша; использовать несколько пригодных ракурсов и физические
  cannot-links. Не связывать тёмные одежды по одному цвету.
- **30–45 min:** сравнить с замороженным baseline на продолжениях, одновременных
  похожих людях, пропусках и границе 120 s; подготовить независимые сцены для review.
  Не считать тот же контроль слепым измерением общей точности.
- **45–55 min:** прогнать CPU/browser проверки, сверить счётчик, поэпизодный экспорт
  и все исходные frame indices/PTS; отдельно показать короткие слабые фрагменты.
- **55–60 min:** зафиксировать версию, SHA256, отчёт и короткий повторяемый сценарий.

Критерий этого часа — меньше фрагментации без роста известных ложных склеек,
воспроизводимый подсчёт и стабильное демо. «Идеальный трекер» и доказанная точность
всей записи за час не обещаются.

## Исправления непрерывности и нумерации

Показанные пользователем старые **377 → 044** относятся к переходу **4 → 5**.
Это был один человек, ошибочно разделённый алгоритмом при развороте внутри
камеры 4. Непрерывный C4-T001 больше не разрезается по одной смене ракурса:
теперь нужны одновременно устойчивая смена appearance/одежды **и** подтверждённый
скачок bbox-траектории относительно её обычного движения. Непрерывный разворот
сохраняет ID. Реальные contamination cuts, в том числе C5-T033, остаются.

Для передачи между камерами добавлен spatial handoff: наблюдаемые направления
входа/выхода, ориентации полей камер и кратчайший допустимый путь по walkable
областям плана. Общий узел находится из пересечения областей, а не по таблице
готовых ID. Несвязанные области/стены, противоположное движение, слишком далёкий
переход, слабая внешность, другая одежда и конкуренты запрещают объединение.
Обычный appearance threshold 0.82 сохранён; 0.72 используется для component cost. Независимая
ветвь handoff дополнительно требует similarity ≥0.72, clothing intersection ≥0.60
и согласованных движений; одна близость точек не считается совпадением.

**C4-T001 → C5-T006/C5-T007 автоматически образуют ID 003** с одним внутренним
ключом G0044. Реальный endpoint gap 0.109 s, путь 0.0387 нормированных единиц,
направления 0.739/0.988, cosine до scene-баланса 0.7233,
clothing intersection 0.7405. Эту пару проверили на исходных crops и в браузере;
в engine нет её локальных номеров или ручного positive review.

Две карточки прежнего ID 288 уже имели один внутренний ID G0288: это два локальных
фрагмента C3-T011/C3-T013. Архив теперь получает `/api/global-tracks` и показывает
**одну карточку ID 019** с обоими интервалами. Технический `/api/tracks` сохранён.

**Отображаемые ID начинаются с 001 по первому появлению**, а не по порядку hash
или старых экспериментов. Это номера глобальных эпизодов, не bbox/детекций.
Внутренний persistent key сохраняется отдельно; одинаковый пересчёт сохраняет
номера и ключи. При смене состава ассоциаций полная offline ревизия может изменить
отображаемую нумерацию — это не online смена ID при переходе человека.

## Плавное воспроизведение и первый выход

Плееры используют **одну исходную шкалу записей организаторов**. Режимы
fallback/estimated и плавающие clock badges удалены из Monitor. API синхронизации,
карта и arrivals overlay больше не присваивают `video.currentTime`. Это происходило
раньше при каждом обновлении часов и вызывало рывки. Теперь позиция меняется только
при открытии видео и явной перемотке пользователя; native video ведёт playback.
Play/Pause/скорость отделены от seek. Исторический Time Alignment остаётся отдельным
инструментом, его данные не переписываются и не управляют просмотром.

Overlay рисуется по фактически декодированным кадрам через video-frame callback,
а не пятью постоянными циклами 60 Hz. Соседние запросы имеют двухсекундное
перекрытие и сохраняют предыдущий buffer. Исправлена граница API: окно ровно 8 s,
без ошибочного запроса на 9 s. ID расположен над человеком, без скачущих badges.

**Сообщённая пользователем ошибка ID 106 ↔ ID 015 исправлена автоматически.**
C1-T001 и C2-T001 теперь принадлежат одному **ID 001**, с одним цветом и одной
движущейся точкой карты. OSNet cosine был 0.7617, ниже обычного 0.82. Простой
порог терял одного человека между видом спереди и со спины.

Дополнительная проверка использует четыре соответствующих неподвижных угла
теннисного стола в обеих камерах. Положение torso в плоскости высоты стола —
приближённая модель, не точная проекция ног. В этой общей плоскости проверяются
совпадение положения, движение, достаточная длительность, одежда, внешность,
конкурирующие кандидаты и конфликты всей компоненты. Глобальный appearance-порог
0.82 не понижен: отдельная ветвь требует сильной независимой геометрии и cosine
не ниже 0.74. Одной похожей траектории или одного цвета недостаточно.

Для первого выхода: 18 пар наблюдений, support 1.744 s, median distance 0.0995
ширины стола, p90 0.1281, direction cosine 0.9996. Pair lag −0.8 s — только
допуск сопоставления, **не offset воспроизведения**. Ни screenshot пользователя,
ни номера этих локальных треков не являются входом engine или hardcoded match.
Ручные landmarks относятся к статичному фону, не к identity labels. Проверялись
первые исходные кадры пяти камер и оригинальный план; private scene references
сохранены в `private_outputs/scene_geometry`. Попытка автоматического floor SIFT
дала лишь 6 вырожденных inliers из 15 matches (condition number ~1.2e8); этот
непригодный fit не использовался для идентификации или точек карты.

План и ракурсы пересмотрены: 1/2 перекрывают foyer у верхнего левого выхода;
3/5 смотрят навстречу вдоль одного коридора, поэтому могут видеть одного человека
одновременно без обязательного появления на 4. Это отражено в topology.
Камера 4 смотрит с восточной стороны в поперечную ветку коридора.

Ранее устранённый `disk I/O error` SQLite не вернулся: backend использует native
Docker volume и закрытый SHA256-bound host snapshot через `mvp publish`.

## Алгоритм и реальные данные

Сохранены 144 110 frame records, 503 ByteTrack-фрагмента и 81 357 observations.
Исходные 390 OSNet track embeddings и 3 427 temporal crop embeddings неизменны.
Новая CPU-подготовка использует уже сохранённые приватные crops и тот же pinned
OSNet. Scene-balanced encoder занял 61.172 s; полное wall time не восстанавливаем
после прерывания финальной записи metadata. Завершённый encoding импортирован
из проверенного кеша без повторного inference. Декодированы только пять первых
кадров существующих source H264 для оценки освещения, полный decode не повторялся.

Pipeline: исходные фрагменты → scene-balanced multi-view appearance → temporal
slices → локальные геометрические bundles → одежда/время/направление/порталы
→ совместная MILP с жёсткими физическими запретами и штрафами внешности
→ общие global IDs для API, видео, карты и архива.

- Нормализация освещения по неподвижному нейтральному участку пола каждой камеры,
  без identity labels. У камеры 3 выраженный жёлтый оттенок; RGB gains
  [0.8503, 0.9416, 1.3123]. Это приближённая компенсация освещения, не цветовая
  калибровка. Clothing histogram допускает соседние оттенки/уровни яркости.
- Несколько поддержанных ракурсов в appearance bank; одиночный чужой crop не
  добавляет новый ракурс. Исходные признаки и происхождение новых сохранены.
- 524 derived tracklets; 21 исходный фрагмент разделён по совокупности устойчивой
  смены внешности/одежды и независимого скачка bbox. Разворот без скачка не режется.
- Torso/full-body duplicate: минимум 12 общих кадров, containment ≥0.90 и
  совпадение высоты головы в ≥85% кадров, согласованный горизонтальный центр,
  различные размеры. Сравнивать embedding торса и полного тела как обязательный
  порог нельзя. Внешность полной фигуры используется совместно; bbox/ByteTrack
  не переписываются. Два отдельных одновременно видимых человека не могут
  объединиться через третий вложенный bbox.
- Короткая окклюзия дополнительно требует минимум двух пригодных crops,
  согласованной позиции головы, same-view gradient signature, внешности и
  однозначного продолжения. Один плохо видимый затылок не подтверждает ID.
- Противоположные коридорные ракурсы определяются из статичной ориентации полей
  камер. Обратные высоты полных фигур должны согласовываться при движении:
  положительный focal scale, correlation ≤−0.86, ограниченный residual,
  ≥16 пар и ≥1.6 s поддержки. Нет произвольного пространственного преобразования,
  подогнанного по людям. Gaps не заполняются искусственными наблюдениями.
- Same-camera reentry: краткое возвращение через тот же image portal,
  одежда/внешность, независимые samples, общий запрет конкурирующих людей.
- Обычный appearance threshold 0.82 сохранён. Отдельная ветвь движения допускает
  более слабую внешность только с независимой геометрической поддержкой.
  Порог 0.72 теперь начало отрицательного component cost: вид спереди/сзади
  не считается физической невозможностью. MILP сопоставляет положительные связи
  со штрафами всей компоненты, без тройного учёта одинаковых partial descriptors.
  Одновременные разные люди одной камеры и запрещённая топология остаются
  жёсткими cannot-links, включая транзитивные пути.
- Отдельный clock budget ±3 s вместо ошибочного суммирования трёх допусков в 9 s.
  Pair lag — только допуск association; к playback и raw PTS не применяется.

Текущая revision `7c105d780c7c9d11dfb9d5c9`. Host-пересчёт под параллельными
CPU-тестами: 124.110 s до accounting, полное время с записью ведомости 137.836 s.
Время зависит от нагрузки; стадии и heartbeat сохраняются в `mtmc/telemetry`.

## Показанные первые фрагменты

Семь source fragments **C3-T001/C3-T002/C3-T004/C3-T006/C5-T001/C5-T002/C5-T003** автоматически
образуют **ID 002**, внутренний G0010. Старые карточки 002/004/005/006 показанного
скриншота заменены одной карточкой с семью фрагментами. В алгоритме нет этих
номеров, таблицы ручных соответствий или чтения контрольных labels.

C5-T002/C5-T003 имеют 73 общих исходных кадра: median containment 0.9872,
area ratio 2.6797, согласованные головы. Torso/full-body больше не конфликтуют.
Для C3-T002↔C5-T003: cosine 0.7851, clothing 0.7332; независимая поддержка
коридорного движения — 22 пары, 3.35 s, inverse-height correlation −0.9275,
relative p90 residual 0.1546. Pair lag 2.8 s не применяется к плеерам.
C3-T003/C3-T005 также образуют один ID 005 после краткой окклюзии.

Отрицательная проверка: едва видимый чужой затылок C5-T206 больше не входит
в группу женщины C5-T204. Сходство фона/градиентов при низком качестве не
разрешает переносить identity. Это важнее простого уменьшения числа карточек.

Возврат на камере 3 в 22–32 s также автоматически входит в **ID 002**.
Дублирующие фрагменты дают один суммарный cross-camera голос, а не несколько.
Умеренное отрицательное cross-view сходство учитывает независимую одежду;
его штраф не обнуляется, сильные противоречия не ослабляются.
Остаточная фрагментация и ошибки на крошечных/закрытых фигурах сохраняются.
Ни схема, ни одежда сами по себе не дают гарантии правильного ID.

## Визуальный контроль и исправленные ошибки

Заморожены 20 информативных baseline cases и добавлены четыре отрицательных
контроля из разных, одновременно видимых людей. Просмотрены последовательности
реальных исходных кадров с точными PTS: общий план и crop, по шесть временно
распределённых наблюдений каждой стороны. Это выборочный визуальный контроль,
а не просмотр всех кадров каждой записи.

Labels используются только `scripts/evaluate_mtmc_control.py`. Engine не читает
их, не принимает готовые соответствия ID и не записывает их в human reviews.
Baseline database и исходный список случаев заморожены.

- **C01 / текущий ID 267 (внутренний G0211):** C4-T082 (raw 1027.516–1045.618), C3-T135
  (1063.155–1076.762), C5-T204 (1066.038–1073.168). Кудрявые волосы,
  полосатый верх и розовые брюки. Автоматически одна группа 4→3→5, один цвет в
  Monitor/Gantt/API. Короткие private previews имеют точные frame/PTS sidecars.
- **C03/C08:** зелёная блуза, чёрная юбка, колготки; 4↔5 — объединены.
  **C06/C12/C15:** длинные волосы, светло-синяя блуза и серые джинсы — отдельная
  группа. Разные люди C21/C22 не склеиваются.
- **C04/C14:** C5-T033 сам меняет человека: чёрная одежда → другой человек в
  синих джинсах. Один embedding на весь source загрязнял межкамерные связи.
  Общая temporal-split логика разделяет его на три части. Точные моменты смены
  не выдаются за ground truth. Два mixed cases исключены из pair metrics.
- **C11:** C5-T158↔C4-T059 раньше не связывались из-за C5-T156, ошибочно
  считавшегося другим одновременным человеком. Проверены 79 общих кадров:
  nested torso/full-body bbox, медианный containment 0.9965, общая голова,
  переменный IoU из-за размеров. Геометрическая проверка дублей устранила ложный
  cannot-link. C11 теперь связан автоматически, без снижения crosscam порога.
- C23/C24 сохраняют разных людей в разных ID. В пяти поздних появлениях C16–C20
  недопустимые **прямые** переходы не выбираются. Это не разметка разных
  личностей или доказательство разделения полного эпизода.

На 17 однозначных случаях: **13/13 положительных продолжений согласованы на всех
проверенных кадрах; 4/4 отрицательных пары разделены**. Baseline: 12/13 и 4/4.
При декартовом сравнении шести кадров каждой стороны: baseline TP=432, FN=36,
FP=0, TN=144; теперь TP=468, FN=0, FP=0, TN=144. Frame-pair precision/recall
здесь равны 1.0; baseline recall — 0.9231.

Это небольшая специально выбранная, повторно использованная контрольная выборка,
**не слепой held-out benchmark**, не 612 независимых переходов и не 100% точности
всего MTMC. IDF1/HOTA и число физических людей не измерялись. Камеры 1/2,
похожие тёмные одежды, длинные окклюзии и все 21 разрез не имеют полной разметки.
Возможны ложные совпадения и лишняя фрагментация. Подробности:
`artifacts/mvp/mtmc/control/quality.json`.

## Миникарта и завершение

На основном плане и во вкладке «Люди» — **одна цветная точка на global ID**, с
небольшой надписью. Прямоугольники зон удалены. Точки меняют положение из bbox
траекторий; статические camera pins остаются для выбора ракурса. Неизвестное
местоположение не заменяется координатой камеры.

`configs/scene_layout.json` содержит source hashes, проверенные статичные image
landmarks и **приближённое** размещение на схеме. Проекция 1/2 общая по столу;
3/4/5 используют видимые границы пола/коридоров. Перспектива, линза, высота тела
и нестрогий масштаб плана дают неопределённость, которая сохранена в JSON.
Близкая экстраполяция ограничивается walkable polygons, далёкая отклоняется.
При нескольких наблюдениях одного ID выбирается один источник; позиции не
усредняются сквозь стены. Видимый marker плавно движется между обновлениями.
Это улучшает отображение маршрута, но не доказывает метрическую калибровку.

Raw PTS, исходные записи, Time Alignment и исторические sync evidence неизменны.
Допуск при association ±3 s и физические transit windows отделены от воспроизведения.
Короткое исчезновение не завершает эпизод. Используется **120 s** отсутствия
при доступном покрытии камер; gaps/неизвестное покрытие остаются lost.
Старый завершённый episode ID не присваивается новому позднему появлению.

**189 CPU pytest passed, 20 Chrome E2E passed.** Проверены геометрические дубли
при разных embeddings, предотвращение транзитивной склейки двух людей,
короткая окклюзия, низкое качество и неоднозначные продолжения, несколько
ракурсов, освещение/одежда, противоположное движение, gaps, глобальные штрафы
и физические запреты, повреждённый/незавершённый кеш и resume без inference.
Существующие 180 тестов сохранены; добавлены 9 проверок accounting/API.

Браузер проверил пять видимых плееров в viewport 1440×2600, 14 s с задержанными
на 500 ms overlay-запросами. Callbacks: 360/359/359/282/360; dropped frames 0,
автоматических seeks 0, движения времени назад 0. Native video по-прежнему управляет воспроизведением; clock/overlay responses
не делают seek. Добавлены preload=metadata, индикатор буферизации и обработка media error. Новый реальный regression проверяет единственную
карточку ID 002 с семью фрагментами и общий ID через API.

Первый нагрузочный API-пересчёт завершился за 148.801 s, но nginx с timeout
120 s вернул 504 раньше завершения. Timeout увеличен до 300 s; прогресс доступен
отдельным коротким запросом, повторный пересчёт получает 409. Финальные HTTP status,

В backend нет torch; native SQLite проходит integrity_check.

Прежний контроль 24 cases: 13/13 однозначных положительных продолжений,
4/4 отрицательных пары разделены. Это повторно использованная малая выборка,
